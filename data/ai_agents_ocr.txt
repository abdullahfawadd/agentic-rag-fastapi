=== Page 1 ===
AI agents are software systems that use a language model to reason about a goal, decide which actions to take, call tools, observe results, and continue until the task is complete. Unlike a simple chatbot that only generates text, an agent has access to external capabilities such as retrieval, calculators, web search, databases, code execution, APIs, and workflow tools. The core idea is to combine language understanding with action. A user gives a question or task, the model interprets intent, selects a tool when needed, and then uses the tool output to produce a grounded answer. This design is especially useful when the answer depends on private documents, current information, or exact computation.

=== Page 2 ===
Agentic RAG extends the traditional retrieval-augmented generation pipeline. In a basic RAG system, retrieval always runs before generation, even when the question does not require documents. An agentic RAG system treats retrieval as one tool among several. The agent can search the vector database for document questions, search the live web for current facts, call a calculator for mathematics, call Wikipedia for stable encyclopedic summaries, or answer directly when no tool is required. This makes the system more efficient, flexible, and transparent. The agent chooses the action based on the prompt, tool descriptions, and the current conversation context.

=== Page 3 ===
The ReAct framework combines reasoning and acting through an iterative loop. The model forms a thought about what information it needs, performs an action by calling a tool, receives an observation, and then decides whether another action is needed. In production interfaces, hidden chain-of-thought should not be exposed, but the application can still show a safe tool trace. A useful trace includes the tool name, the tool input, and a preview of the tool output. This gives students and users visibility into why the answer was produced and which external systems were used.

=== Page 4 ===
Tool design is critical because the language model relies on tool names, parameter schemas, and descriptions to decide when to use each capability. A vague description such as "search" can make the model overuse a tool. A strong description says what the tool is for and what it should not be used for. For example, the knowledge-base search tool should be described as useful for the uploaded AI agents PDF and domain-specific course material, but not for arithmetic, current events, or Wikipedia summaries. Clear tool boundaries improve reliability and make demonstrations easier to evaluate.

=== Page 5 ===
The knowledge base uses semantic embeddings and a vector database. Each PDF page is split into overlapping chunks, and each chunk is embedded with the BAAI/bge-small-en-v1.5 model. Pinecone stores the vectors with metadata such as source filename, page number, chunk index, and text. During a query, the user question is embedded and compared with the stored vectors. The top matches are returned to the agent as context. Page metadata is preserved so the final answer can include citations, which is important for academic work and grading because the answer can be checked against the source.

=== Page 6 ===
A live web-search tool is useful for information that changes over time, such as recent AI agent frameworks, current product releases, news, competitions, or events. A vector database cannot answer these questions unless the documents have been updated. Tavily or a similar search API can return current snippets and URLs. The agent should use web search only when freshness matters or the PDF does not cover the topic. For stable background explanations, Wikipedia may be a better tool. For PDF-specific content, the knowledge-base tool should be preferred.

=== Page 7 ===
The calculator tool handles exact numeric tasks such as powers, percentages, unit conversions, and date arithmetic. It should be implemented safely, using an expression parser instead of unrestricted eval. Safe calculation prevents arbitrary code execution while still letting the agent answer questions such as "What is 2 raised to the power of 16?" or "How many days are in five years?" A calculator is a simple but powerful demonstration of tool selection because the agent should not waste vector search or web search calls on arithmetic.

=== Page 8 ===
A production agentic RAG application should protect secrets, validate inputs, log tool usage, and provide observability. API keys should live in environment variables or a secret manager, not in committed code. Tool logs should record timestamp, tool name, input, and success or failure so developers can debug agent behavior. The system should enforce rate limits, timeouts, maximum agent iterations, and safe error handling. A user interface should make citations and tool traces visible without exposing private chain-of-thought. These practices make the agent more trustworthy and easier to maintain.
